# SSOptimizer 独立启动设计

独立启动从已有 Starsector 0.98a-RC8 安装读取核心 JAR、资源和平台原生库。游戏继续使用安装目录中的模组、启用列表、设置、存档、日志和截图。独立启动器管理自己的程序文件、运行锁和缓存。Windows 安装与升级使用发行签名，相关命令见[安装与发布说明](../../packaging/standalone/README.md)。

## 命名空间与准备范围

| 入口 | 游戏类 | 用户模组 | 映射 |
| --- | --- | --- | --- |
| `obf` | 使用安装中的 obf 游戏。在 RFB 请求读取或定义类时，修复 Java 25 拒绝的 JVM 标识符。 | 使用启用模组的声明 JAR。合法 obf 字节按原加载规则使用。 | 构建机将 SSOptimizer 的游戏引用和注入选择器写为目标 obf ABI。玩家包不含完整映射。 |
| `dev` | 准备阶段将四个固定游戏核心 JAR 中的 obf 输入转换为 named，后续启动复用缓存。 | 只转换已启用模组在 `mod_info.json` 中声明的 obf JAR，已标记为 named 的归档直接挂载。 | 使用开发发行包中的 Tiny 映射。 |

引导器读取 `mods` 一级子目录的 `mod_info.json`，用模组 ID 匹配游戏的启用列表，并按游戏顺序处理其中声明的 JAR。RFB 在启动器的私有工作目录中发现插件。运行时按原始 JAR 的位置解析 manifest 声明的依赖，dev 缓存只记录参与转换和继承解析的输入。

## JVM 与类加载

1. 管理入口选用 Java 25，设置工作目录、模块开放、原生库位置和用户启动参数，再启动 RFB Main。
2. 独立 tweaker 配置系统域与游戏域、挂载游戏输入、模组及共享优化负载，再完成 Mixin 初始化。类变换由 RFB、LaunchWrapper 和 Mixin 执行。
3. RFB 系统域负责其中定义的原生窗口与输入类。游戏域在目标首次定义前规范化或重映射所需字节，应用 HybridWeaver 与 GL 重定向，再应用 Mixin。Mixin 的类查询应取得同一命名空间的未织入字节，禁止在查询中提前定义目标类。
4. 游戏入口接收用户参数。Janino 在当前启动所使用的游戏命名空间中编译脚本。自建类加载器处理遵循 JDK 定义域，保留来源、资源、保护域和包访问规则。普通模组遵循统一规则。

NanoForge 使用其自身的类加载与插件生命周期。独立 tweaker 的配置只在独立入口注册。独立运行仍保留 `ssoptimizer.disable.*`、渲染线程开关和 bridge/direct Mixin 选择。XStream 使用游戏启动配置或用户指定的库，兼容差异按实际 API 与类结构处理。参见 [RC8 与 Java 25 兼容记录](standalone-rc8-java25.md)。

## 玩家数据与发布验收

安装、启动、切换版本、卸载和重新安装不得复制、覆盖或迁移玩家存档、设置与模组勾选。独立入口不提供实例管理和旧档转换命令。以隔离的游戏安装副本验证首次启动、修改模组勾选、新建战役、战斗、保存和冷启动读回。覆盖 Windows 英文与常规汉化 RC8，Linux 结果按实际游戏字节码和 native 组合记录。

默认发行流程检查受签名管理的程序文件。完整类探针、字节码诊断和面向实际游戏的织入回归属于另行发起的开发工作。发布构件与 obf 兼容细节见 [RC8 的 obf 正式包与 dev 开发包](obf-release-reobf.md)。
